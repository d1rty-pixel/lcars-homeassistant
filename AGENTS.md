# Working on this repository

An LCARS dashboard for Home Assistant, generated by one Python script and rendered by LCARdS plus a
few light custom cards. There is no dashboard YAML to edit: change the generator and deploy.

## Where things are

- `generator/build_dashboard.py`: builds the whole Lovelace config (`build/lcars_dashboard.json`).
  One `*_view()` function per view returns its content and frame options for `view()`.
- `ha/www/*.js`: the custom cards (`lcars-*`), deployed to HA's `/config/www`.
- `docs/DESIGN.md`: **every design rule and decision**, the page descriptions and the helper overview.
  Read it before changing a layout; keep it in step with every design change.
- `docs/OPERATIONS.md`: tablets, layout checks (screenshots), known limitations.
- `docs/integrations/`: what each view needs from HA.
- `site.yaml` (git-ignored; template `site.example.yaml`): the installation's hosts, devices, location.

## Build and deploy

```bash
python3 generator/build_dashboard.py              # build (reads live data from HA)
python3 tools/validate.py build/lcars_dashboard.json
python3 tools/deploy.py                           # build + validate + save; backs up the live config first
bash tools/deploy_ha_files.sh                     # after changing ha/www/*.js or the theme
python3 tools/deploy.py --restore build/backups/<file>.json
```

The build and the host-file deploy need the HA token and SSH access described in `README.md`.

## Rules that are easy to miss

- **Check layouts at 1280×720, 1280×800 and 1920×1080** after any layout change (screenshots: see
  `docs/OPERATIONS.md`). No page may scroll; content that doesn't fit is not rendered (display
  priorities), shoulders go first.
- Follow the page frame and colour rules in `docs/DESIGN.md` (one label column, titles in bars,
  one colour family per frame, pills via `pill_shape()`, codes via `lcars_code()`, palette constants
  only). All UI text is English.
- Card behaviour belongs in `ha/www/*.js`, sizes and colours come from the generator's config.
- Test interactive changes in a browser without side effects on the real devices (e.g. stub the
  service call) when pressing a button would change real state.

## Public repository: no site data

The repository is public. Tracked files stay generic: no hostnames, IPs, names, coordinates, serials
or entity IDs that identify the installation. Site-specific notes belong in the git-ignored
`CLAUDE.local.md` (or `site.yaml`). Before every push, search the tracked files for the
installation's identifiers (the local notes keep the exact check).
